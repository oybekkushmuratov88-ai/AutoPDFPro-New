# Молниезащита — десктопное приложение

Техническое задание и план перехода с HTML-прототипа на полноценное приложение.

---

## 1. Что уже готово

`lightning.ts` — ядро расчёта, **проверено 50 тестами** по первоисточникам:

| Методика | Источник | Проверено по |
|---|---|---|
| `RU` | РУ 9504тм-Т1, Прил. 1, стр. 56–59 | номограммы листов 11 и 13, критерий стр. 57 |
| `B` | РН 34-301-388:2016, зона Б (≡ РД 34.21.122-87) | Lightning Calculation Report, Step-Up/EIF Station |
| `A` | РН 34-301-388:2016, зона А | те же формулы, коэффициенты зоны А |

Реализованы также:

- **усечение вершины зоны** стержневого молниеотвода высотой 60–250 м
  (п.1.2, стр. 57): Δh = 0,5(h − 60) при 60 < h ≤ 100; Δh = 0,2h при
  100 < h ≤ 250; при ha < Δh защиты нет;
- **тросовые молниеотводы** (Приложение 2, стр. 60): rx = k1·ha/(1 + hx/h)
  при h < 30 м и то же с множителем P при 30–250 м; Δh = 0,29(h − 30)k2
  либо 0,2·h·k2; k1 = 1,2 / k2 = 1,0 при прорыве 10⁻², k1 = 0,6 / k2 = 1,3
  при 10⁻³. Поддержан параболический провис троса между опорами;
- **условие защищённости площади между тремя молниеотводами**
(РУ 9504тм-Т1, стр. 58): Д ≤ 8·ha при h ≤ 30 м, Д ≤ 8·ha·P при 30 < h < 250 м,
где Д — диаметр окружности через центры трёх молниеотводов. Источник (стр. 58)
допускает определять зону произвольного числа молниеотводов суммированием
зон любых трёх соседних — `coverageAt` проверяет все тройки.

Ядро не зависит от DOM и переносится в любой стек без изменений.
**Переписывать его не нужно** — любая правка требует повторного прогона тестов.

Экспортируемое API:

```ts
coefP(h)                                  // поправочный коэффициент P
singleZone(h, hx, method)                 // h0, R0, Rx, P
pairZone(h1, h2, L, hx, method)           // hc, Rc, Rcx, Lcr, d, Leff, tw, joined
halfWidth(Rx1, Rcx, Rx2, t, tw)           // полуширина зоны вдоль оси пары
tripleZone(A, B, C, hx, method)           // условие Д <= 8·ha·P (стр. 58)
rodTruncation(h)                          // Δh для стержневого МО 60-250 м
cableCoefs(reliability)                   // k1, k2 тросового МО
cableTruncation(h, reliability)           // Δh тросового МО
cableZone(h, hx, reliability)             // полуширина зоны троса
cableHeightAt(cable, t)                   // высота троса с провисом
cableCoverage(x, y, hx, cable)            // защищена ли точка тросом
coverageAt(x, y, hx, rods, method)        // защищена ли точка плана
computeLevel(hx, rods, targets, method)   // полный отчёт по уровню
rasterise(bounds, cell, levels, rods, m)  // карта зон для заливки
zoneCeiling(x, y, rods, method)           // высота границы зоны — для 3D-меша
```

## 2. Стек

Рекомендация: **Tauri 2 + React + TypeScript + Three.js**.

| | Tauri | Electron |
|---|---|---|
| Установщик | 8–15 МБ | 120–180 МБ |
| Память | ~80 МБ | ~300 МБ |
| Бэкенд | Rust | Node.js |
| Требует при сборке | Rust toolchain | только Node |

Electron — запасной вариант, если возня с Rust мешает. Весь остальной код
идентичен: React, Three.js и ядро переносятся между ними без правок.

```
npm create tauri-app@latest   # React + TypeScript
npm i three @react-three/fiber @react-three/drei zustand
npm i -D vitest @types/three
```

Библиотеки:

- **three / @react-three/fiber** — 3D-сцена
- **@react-three/drei** — OrbitControls, Grid, Html-подписи
- **zustand** — состояние проекта (молниеотводы, уровни, объекты)
- **vitest** — тесты ядра (перенести `lightning.test.ts`)

## 4. 3D-визуализация

Главное отличие от прототипа. Поверхность зоны строится по `zoneCeiling`:
для каждой точки плана бинарным поиском находится максимальная высота,
на которой точка ещё защищена. Получается «шатёр» — ровно тот вид,
что на референсных картинках коммерческих пакетов.

```ts
const N = 160;                       // сетка 160×160 достаточно
const geom = new THREE.PlaneGeometry(W, H, N - 1, N - 1);
const pos = geom.attributes.position;
for (let i = 0; i < pos.count; i++) {
  const x = pos.getX(i) + originX;
  const y = pos.getY(i) + originY;
  pos.setZ(i, zoneCeiling(x, y, rods, method));
}
geom.computeVertexNormals();
```

Материал: `meshPhysicalMaterial`, `transparent`, `opacity 0.35`,
`side: THREE.DoubleSide`, цвет по уровню. Сверху — `wireframe`-слой
тонкими линиями, как на референсе.

Производительность: 160×160 = 25 600 вызовов `zoneCeiling`, каждый — около
10 итераций бинарного поиска. Считать в **Web Worker** и кешировать,
пересчитывать только при изменении молниеотводов или методики.

Оборудование — боксы высотой `hx`, красятся по `coverageAt`:
зелёный внутри зоны, красный снаружи. Сразу видно, что торчит наружу.

## 5. Функции сверх прототипа

Порядок — по отдаче:

1. **3D-сцена** с вращением, сечением плоскостью, экспортом кадра
2. **Импорт DXF** подложки — план ПС прямо в сцене, без ручной калибровки
3. **Экспорт зон в DXF** — контуры зон слоями, вставляются в рабочий чертёж
4. **Мультипроект** — несколько ПС в одном окне, вкладками
5. **Расчёт по трём методикам одновременно** — таблица сравнения в отчёте
6. **Библиотека типовых молниеотводов** Энергосетьпроект
   (16,85 / 19,35 / 21,8 / 24,3 / 26,47 / 27,05 / 30,5 / 32,19 / 38,24 м)
7. **Оптимизатор** — подбор минимальной высоты, при которой все объекты
   попадают в зону (простой перебор с шагом 0,05 м)
8. **Отчёт в Word** через `docx` — редактируемый, а не только PDF

## 6. Известные ограничения ядра

Фиксировать в документации приложения, чтобы не забыть:

- Ширина `bx` методики RU — гиперболическая интерполяция, точная в обеих
  крайних точках; в середине диапазона расходится с номограммами
  до ~0,5 м. Кривые листов 11 и 13 оцифрованы не полностью.
- Ширина bx методики RU в середине диапазона расходится с номограммами
  до ~0,5 м (в запас). Крайние точки точны.
- Тросовые молниеотводы: реализован **одиночный** трос (П.2.1–П.2.3).
  Совместная зона двух тросов и комбинация «трос + стержень»
  в источнике даны графически (лист 7) и не реализованы.
- Взаимодействие стержневых и тросовых молниеотводов не учитывается:
  `coverageAt` и `cableCoverage` считаются независимо, их результаты
  нужно объединять по «или».
- Высоты свыше 250 м выходят за пределы методики (`rodTruncation`
  и `cableTruncation` вернут NaN).

## 7. Порядок работ

1. `npm create tauri-app` → перенести `core/` → прогнать тесты
2. Панели ввода + 2D-план (перенос логики прототипа)
3. 3D-сцена: площадка, мачты, поверхность зоны
4. Разрез и таблицы результатов
5. PDF-отчёт
6. Импорт/экспорт DXF
7. Сборка установщика: `npm run tauri build`

Пункты 1–3 дают работающее приложение, остальное наращивается поверх.
